O Problema

A jornada do pet acontece em 4 momentos reativos

Hoje, clínicas e tutores só se encontram quando algo dá errado. O resto da vida do pet acontece num vácuo de informação.

Clínicas
Perda de recorrência e abandono de tratamentos.
Tutores
Esquecimento de datas e insegurança sobre a saúde do pet.
Pets
Agravamentos evitáveis por falta de cuidado preventivo.
Entre esses 4 momentos — o pet fica invisível para o ecossistema veterinário.

Proposta de Valor

Transformamos cuidado reativo
em jornada contínua

Uma única infraestrutura conecta clínica, veterinário e tutor — substituindo planilhas, WhatsApp e papel por um fluxo proativo e auditável.

B2B
Para Clínicas
Maior retenção de pacientes e LTV aumentado com follow-up automatizado. Tutores que voltam — sem ligar.
B2C
Para Tutores
Nunca perder um alerta crítico de saúde do pet. Calendário, prontuário e contato com a clínica em um só lugar.
IA
Para o Sistema
Luna reduz urgências desnecessárias com triagem inteligente antes da consulta — protegendo o calendário do veterinário.
B2B2C · Clínica + Veterinário + Tutor · Ecossistema integrado
Jornada To-Be

De reativo para contínuo — em 6 etapas

A primeira etapa pertence ao mundo de hoje. As cinco seguintes são Kura.

Antes 01 📱 Tutor abre o app Kura App · React Native
Com Kura 02 📅 Agenda online kura-tutor · Java / Spring
Com Kura 03 🔔 Alerta automático Firebase Cloud Messaging
Com Kura 04 🩺 Vet consulta prontuário kura-api · .NET / C#
Com Kura 05 🤖 Luna faz pré-triagem Python · YOLOv8n
Com Kura 06 📊 Clínica vê métricas Dashboard analítico
AS-IS

Tutor liga, agenda por WhatsApp, esquece da vacina, volta na emergência.
TO-BE
Com Kura
Tutor recebe alerta, agenda no app, Luna pré-tria, clínica enxerga o histórico contínuo.
Arquitetura Técnica

Cinco camadas. Um ecossistema integrado.

Mobile
App Tutor · App Clínica · React Native
Onboarding invite-based · token gerado pela clínica · OTA updates via Expo.
APIs
kura-api → .NET / C# · kura-tutor → Java / Spring
JWT stateless · Optimistic locking cross-API · OpenAPI 100% documentado.
IA · Luna
luna-service · Python · YOLOv8n + MobileNetV3
Computer vision para pré-triagem · sempre com disclaimer "procure um veterinário".
IoT
ESP32 → /api/v1/iot/leituras
Monitoramento de temperatura de internações em tempo quase-real (REST / MQTT).
Dados
Oracle 19c · Schema compartilhado · Flyway migrations
.NET e Java versionam o mesmo schema · ownership por tabela · H2 como fallback DevOps.

Quadrante de Posicionamento
Diferenciais

Seis decisões de arquitetura que nos protegem

01
Schema Oracle Compartilhado
.NET e Java sincronizados em tempo real sobre o mesmo schema — sem API Gateway extra e sem polling.
kura-tokens.sql
02
Luna — Computer Vision
Triagem de sintomas antes da consulta. Reduz urgências desnecessárias sem substituir o veterinário.
YOLOv8n + MobileNetV3
03
IoT Nativo
Monitoramento de temperatura de internações via ESP32 — leitura contínua chega direto na API.
MQTT / REST
04
Onboarding Invite-Based
Tutor só acessa o app com token gerado pela clínica — vínculo auditável e sem spam.
JWT + invite_token
05
Optimistic Locking Cross-API
Agendamentos sem conflito entre app do tutor e sistema da clínica — versões reconciliadas no servidor.
ETag + 409 Conflict
06
LGPD by Design
Consentimentos com idempotência e relatório Art. 18 automatizado — pronto para auditoria desde a Sprint 1.
LGPD Art. 18
